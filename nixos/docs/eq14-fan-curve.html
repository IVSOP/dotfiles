Hysteresis, delays and response speed

Hysteresis is memory expressed as a temperature gap. In a hypothetical controller with actual on/off thresholds of 50°C and 45°C, the fan starts on warming to the on threshold and stays on while cooling through 49°C, 48°C and so on, until the off threshold is reached. While between 45°C and 50°C, the previous on/off state matters. This avoids toggling around a single threshold. This is a general example, not a verified description of the EQ14’s current register settings.

The inspected PWM2 interface exposes automatic curve points, starting PWM, slope, temperature mapping, mode and carrier frequency. It exposes no configurable start delay, averaging window or spin-up/down duration. Beelink’s published EQ14 instructions also list curve settings rather than these timing controls. This does not establish that the silicon has no internal smoothing; it means no supported control for changing it has been identified here.

If short bursts later cause objectionable starts or speed changes, filtering and response timing would be worth investigating. First verify the temperature thresholds and actual start/stop behavior with the current automatic controller. Do not treat slope, carrier frequency or sensor polling as substitutes for a delay. A custom temporal policy would require a supported firmware option or a continuously running software controller, which this Nix service does not provide.

Why start at 50°C?

You report that the machine is usually below 55°C. The fan controller uses a different sensor from the CPU package: a saved snapshot recorded 40°C at controller temp1 and 51°C at the CPU package. A later reading was 39°C and 50°C respectively. These snapshots do not establish a fixed offset, particularly during bursts of CPU activity.

For that reason, the current configuration uses 50°C on the controller rather than 55°C. Compared with the original curve, it raises the startup register by 10°C, increases the running slope, and lowers the full-speed threshold by 20°C. It aims to reduce idle noise while bringing cooling in more strongly once temperatures rise. It does not establish that the machine can remain below 55°C with the fan stopped.

Check before relying on it

This is not a manufacturer-approved or fully thermally validated curve. A short observation confirmed stopping and restarting. Sustained normal workloads, including storage activity, and longer idle periods still need to be checked for stable CPU package, controller and SSD temperatures. Retain automatic control and thermal protections. The fan may remain running after warming above the on threshold until it cools below the stop boundary; being below 50°C alone does not imply it must be off.

The first live check used an extra 4°C hysteresis delta (absolute readback 41°C). The fan was observed stopped at controller temp1 41°C, then running again in later samples at 42°C; the exact restart temperature was not captured. The subsequent zero-offset revision was confirmed applied and produced the historical samples below. It stopped the fan, but did not produce the claimed 45°C-off / 50°C-on gap. The present configuration supersedes that revision with off register 50°C and offset 3°C, and its settings have now been verified on hardware.

If temperatures keep climbing, the CPU throttles, or the fan fails to restart, restore the original settings. The controller’s sensor location and lag are not calibrated here; there is no validated conversion to CPU package temperature.

As conservative validation goals rather than manufacturer limits, aim to keep sustained CPU temperature below about 80–85°C and SSD composites below about 60–65°C. Check for thermal throttling and SSD thermal warnings as well; those have not been inspected in this session.

What 6 W “base power” means

Intel’s N150 listing gives 6 W Processor Base Power. This is a thermal-design reference validated in the base configuration under an Intel-specified demanding workload. It is not the CPU’s universal maximum, minimum, idle power or a wall-socket measurement. Idle consumption can be lower and boosted operation can exceed it. The system vendor’s configured power limits also matter.

This machine’s RAPL interface reports 20 W long-term and 25 W short-term limits, with a long-term averaging window of about 28 seconds. Those are configured limits, not measured present power draw, and not a statement that total system consumption is capped at 25 W. No power settings were changed. The 6 W label therefore does not mean the heatsink only ever needs to dissipate 6 W.

A large heatsink helps absorb short bursts and spread heat, but long-term cooling depends on transferring that heat out of the case. CPU power is only part of the heat load; SSDs, memory and power circuitry also contribute. The heatsink’s apparent size alone cannot establish fanless operation under sustained load. Automatic fan stop during light workloads is more defensible than permanently disabling the fan.
